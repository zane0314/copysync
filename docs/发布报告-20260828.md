## 二、Android 本次修复

用户反馈的问题已逐项定位并修复：

| # | 现象 | 根因 | 修复方案 |
|---|------|------|----------|
| a/b | 登录正常但取不到传输历史 / 临时网盘 | 恢复会话未持久化服务器地址（baseUrl），且恢复 token 后未触发数据拉取 | `restoreSession` 持久化并优先读取已存 baseUrl；恢复 token 后 `unawaited(refresh())` 自动拉取 |
| c | 上传报「网络错误：connection closed before full header was received」 | 100–110MB 区间服务端在读 body 前 early-413 并关连接，经 nginx 表现为上游错误 | 客户端 `maxUploadBytes = 100MB`（对齐服务端 `MAX_FILE_BYTES`）提前抛 413，永不触达该路径 |
| d | 从「选择文件」上传大文件屡次报错并停止运行 | Dart 上传、Android picker 与“保存已发送文件”存在整包内存/MethodChannel Base64 路径，触发 OOM | Dart 上传改为 `openRead()` / `addStream`；Android SAF picker 与已发送文件落盘改为原生路径流式复制，并在复制前/过程中执行 100MB 守卫 |
| e | 28 版真机显示已登录，但网盘/历史为空且刷新、上传连接重置；更新检查正常 | 升级保留旧 token，但旧安装没有后来新增的 baseUrl 存储项；Android 生产默认值仍错误指向 Emulator 专用 `10.0.2.2` | 生产默认 API 基址改为 `https://copy-direct.example.com`；开发/Emulator 可用 `COPYSYNC_BASE_URL` 编译期覆盖 |

### 代码变更

- `lib/api/api_client.dart` — 流式 `uploadFile` + 100MB 守卫；移除废弃的 `_encodeMultipart`
- `android/.../CopySyncBridge.kt` / `MainActivity.kt` — 原生 SAF picker；已知大小提前拒绝、未知大小边复制边限流；已发送文件按缓存路径流式落盘
- `lib/bridge/android_*` — picker 与路径式保存桥接，不再通过 MethodChannel 传大文件字节
- `lib/state/app_state.dart` / `lib/ui/{inbox_page,drive_page}.dart` — 保存完成后再清理 picker 缓存，消除删除竞态
- `lib/state/token_store.dart` / `test/memory_token_store.dart` — baseUrl 持久化（`clear()` 时保留）
- `lib/state/app_state.dart` — `login` 保存 baseUrl；`restoreSession` 优先读取已存值并自动 `refresh()`
- `test/api_client_test.dart` — 新增「超 100MB 直接抛 413，且不发起请求」测试
- `lib/main.dart` / `test/main_test.dart` — 修复生产默认 API 基址并增加回归测试
- `pubspec.yaml` — `2.0.0+26` → `2.0.1+27` → `2.0.2+28` → `2.0.3+29`
