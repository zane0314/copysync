# CopySync V3 Completion Gate 技能设计

> 目标：创建供 Kimi 与 Codex 共用的 `copysync-v3-completion-gate`，在 CopySync V3 阶段完成、发布候选、推送和最终完成前强制核验证据。

## 1. 权威来源与范围

技能只约束 CopySync V3，唯一产品权威是：

`docs/superpowers/specs/2026-08-24-copysync-v3-flutter-api-ui-rebuild-design.md`

技能不得复制完整产品规则形成第二份真相。未来 V4 不自动继承 V3 门槛。

技能安装到共享目录：

`$HOME/.agents/skills/copysync-v3-completion-gate/`

保持自动发现，不设为显式调用专用。

## 2. 结构

只创建：

```text
copysync-v3-completion-gate/
├── SKILL.md
└── agents/
    └── openai.yaml
```

不创建检查脚本、复制版清单、README 或无用途目录。GUI、真机和线上证据不能由脚本可靠判定；产品规则由主设计文档维护。

## 3. 自动触发

以下情形必须加载技能：

- CopySync V3 的 API、SQLite 迁移、Flutter、Mac/Android 原生桥接、网页、图片剪贴板、UI、构建、更新或部署发生变更后；
- 准备声称阶段完成、功能完成、发布候选可用、已经发布或线上完成之前；
- 服务端、新网页、Mac、APK 准备推送之前及推送之后。

普通只读咨询、尚未进入完成判断的单一代码阅读或未来 V4 工作不触发。

## 4. 输入与证据流

```text
V3 主设计 + .ai/HANDOFF.md + Git/测试/构建事实
+ 网页/Mac/Android Emulator GUI 记录 + Android 真机记录
→ 判断当前阶段和适用门
→ 逐项 PASS / FAIL / UNVERIFIED / N/A
→ 允许完成或输出“未完成”
```

技能先定位 Git 根目录，完整读取主设计和 `.ai/HANDOFF.md`，再核对实际 Git 状态、测试、构建、签名、包、运行状态和 GUI 证据。交接文件和口头说明不是高于实际状态的证据。

## 5. 门禁规则

- 主设计缺失、不可读或不是已批准版本时，直接判定未完成。
- `N/A` 必须给出可核实理由，不能用于绕过现有功能零回退矩阵。
- 自动测试不能替代网页、Mac、Android Emulator 的 GUI 模拟手动操作。
- Android Emulator 不能替代真实 Android 的后台、剪贴板、分享和更新冒烟。
- HTTP 200、编译成功、单张截图相似或单个平台通过均不足以完成。
- 发布前必须验证迁移备份与回滚、签名、版本、SHA-256、更新清单、覆盖安装和功能矩阵。
- 发布后必须重新验证线上登录、发送、收件、图片粘贴、下载和更新链路。
- 证据必须新鲜、可追溯到命令、运行记录、GUI 操作或截图；不接受“应该可用”和旧任务结论。
- 技能不得自动扩大发布权限；真正推送前仍须 Zane 最终 go/no-go。
- 不记录或输出密码、Token、Cookie、私钥或带凭据 URL。

## 6. 阶段适用性

### 6.1 工作单元或内部阶段

只检查该阶段已承诺的功能、测试和回归，并明确后续未完成项。通过内部阶段不能表述为 V3 整体完成或可发布。

### 6.2 发布候选与推送前

检查主设计中的全部自动验证、GUI 人工门、Android 真机、视觉对照、功能零回退、迁移、回滚、签名、版本、更新清单和线上切换准备。

### 6.3 推送后与最终完成

除发布前证据外，还必须检查线上服务、网页、Mac 更新、APK 更新以及登录、发送、收件、图片粘贴、下载和更新链路的实际结果。

## 7. 输出规则

所有适用门都有新鲜证据并通过时，输出简洁 PASS 报告：

- 当前阶段；
- 通过的适用门和关键证据；
- 明确的 N/A 及理由；
- 仍存在但不阻止该阶段的限制。

任一适用门失败或无证据时，第一行必须是 `未完成`，随后只列：

- `FAIL` 或 `UNVERIFIED` 项；
- 已确认的最窄事实；
- 下一步唯一动作。

不得用“基本完成”“应该没问题”“可先发布再验证”等表达绕过门禁。

## 8. 与其他技能的关系

- `project-handoff` 维护恢复状态；完成门仍须核对实际事实。
- `test-driven-development` 约束实现过程；完成门检查真实 red/green 与回归结果。
- `webapp-testing` 提供网页自动证据；不能替代浏览器 GUI 手动模拟。
- `browser:control-in-app-browser` 与 `computer-use` 提供 GUI 操作证据。
- `verification-before-completion` 负责单项完成声明的新鲜验证；本技能负责 V3 跨层整体门禁。

主设计文档的“技能使用页”是调用顺序权威。

## 9. 技能验证

创建后必须：

1. 运行 `quick_validate.py`，验证名称、frontmatter 和占位符；
2. 使用一个“只有单元测试、缺少 GUI/真机证据”的模拟项目状态，结果必须为 `未完成`；
3. 使用一个包含无法追溯口头声明的状态，确认技能不会把声明当证据；
4. 检查自动触发描述只覆盖 V3 完成/发布工作，不吸引普通 CopySync 咨询或 V4；
5. 确认技能不包含产品规则复制、发布命令或任何凭据。

## 10. 完成标准

- 技能位于共享目录并通过格式校验；
- 自动触发描述精确；
- 主设计路径可发现且被声明为唯一权威；
- 两个负向行为测试均拒绝错误完成声明；
- V3 主设计包含完整技能使用页；
- 无脚本化 GUI 假验证、无重复产品规则、无权限扩大。
