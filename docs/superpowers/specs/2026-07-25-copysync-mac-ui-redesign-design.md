# CopySync Mac App UI 对齐 web + 行为优化（V3 预览定稿）设计文档

日期：2026-07-25
状态：V3 预览已发用户确认流程中（mac-ui-v3.html）
前置：P1（web）、P2（安卓）已完成上线；Mac App = 原生 Objective-C 壳（mac-clipboard/CopySync.m，1465 行）
+ WebView 内容（app.py 的 `?app=mac`，深色）

## 一、需求提炼

### A. 主窗口（原生壳 + WebView 内容）
1. **视觉**：整体对齐 web 方案 B（米白底 `#faf9f7`、白卡片、墨绿 `#0b5c3e`、14px 圆角、细线），
   **取消深色底**（WebView `body.mac-app` 深色样式整套换白）。
2. **左导航**（原生 sidebar）：顺序为 **收件箱 / 传输历史 / 临时网盘 / 设备 / 打开网页版 / 设置**（底部）。
   - 「跨设备」改名「**收件箱**」（图标换托盘线条图标）
   - 第二行新增「**传输历史**」：完整传输记录（含已过期灰显，保留 30 天，数据来自 P1 history）
   - 「本地历史」→「**临时网盘**」：内容换为与 web/手机一致的网盘（钉子 -45°/斜钉、续期 +7 天、
     复制/下载/删除、默认 7 天）
   - 「**打开网页版**」从内容区右上角移入左导航（原 `mac-open-web` 按钮移除）
   - 全部换线条图标
3. **收件箱内容区**：
   - 标题改「收件箱」；顶部新增**上传文件框**（与 web 相同的虚线拖放框 + 上传按钮，
     复用 drive 上传链路，默认 7 天）
   - 发送栏：目标默认 **Android 手机**（删「全部设备」，三端规则 Mac→Android）；
     粘贴文本/选文件/选照片换线条图标
   - 「最近传输」→「**我的文件**」（与 web 相同：图标 + 名称 + 方向/剩余时间 +
     行内「上传 · 下载/复制」，上传=转存网盘 /api/items/<id>/keep）

### B. 历史剪贴板浮窗（原生面板）
4. **透明毛玻璃**：高度透明（桌面明显透出）+ 高斯模糊保证可读，参考 V3（约 22% 白底 + 34px 模糊）。
5. 每条一个框；**上传（云上传）/发送（纸飞机）/复制（图标）+ 钉子全部固定行尾**，
   不随文字长短移动；**钉子固定在最右端**（钉住=斜钉绿、未钉=-45° 灰半透明）；
   文字超出省略号。编号、缩略图保留。

### C. 快捷键行为（原生）
6. **两个快捷键完全独立**：收件箱（⌘.）与历史剪贴板（⌘,）互不带出
   （当前按收件箱快捷键会连带显示历史剪贴板，需修复）。
7. **切换语义**：窗口已显示时再按快捷键 = 隐藏；**例外：历史剪贴板存在已钉住内容时不隐藏**
   （收件箱无此例外）。

### 明确不做（YAGNI）
- 不改接收/发送链路、原生桥（webkit messageHandlers）、截图快捷键（⌘J）、菜单栏图标与菜单结构
- 不改 web / android 端（本次只动 mac 壳与 ?app=mac 视图；共享接口零改动、不新增后端接口）
- 本地剪贴板历史条目数量（10 条）与"复制不自动上传"策略不变

## 二、检验目标（验收标准）

### 构建与回归
1. `python3 test_app.py` 22 项全部通过（mac HTML 断言如有变化只改断言不改逻辑）。
2. Mac 源码测试脚本（test-source.sh / build-dmg.sh）通过；新 DMG/ZIP 构建成功，版本号递增（build 34）。
3. app.py 改动不破坏 web / `?app=android`（截图回归）。

### 界面核对（逐项截图）
4. 主窗口：白底方案 B、无深色残留；左导航六项顺序正确、线条图标、选中态正确；
   「打开网页版」在导航中可点开浏览器。
5. 收件箱：标题正确；上传框可拖入上传（默认 7 天）；发送栏默认 Android 手机、无「全部设备」；
   我的文件行内 上传/下载/复制 可用（转存后临时网盘可见）。
6. 传输历史页：显示完整记录，过期条目灰显「已过期 · 文件已删」。
7. 临时网盘页：钉子切换、续期 +7 天、复制/下载/删除正常，与 web 网盘数据一致。
8. 历史剪贴板：透明毛玻璃（桌面透出）；操作图标+钉子固定行尾对齐（长短文本逐条核对）；
   钉子在 最右端、两态正确。
9. **与 V3 预览图一致，任何元素无重叠；所有按钮有反馈**（悬停/按下态）。
10. 快捷键：收件箱与历史剪贴板各自独立开关；已显示再按隐藏；
    历史剪贴板有钉住内容时按快捷键不隐藏；⌘J 截图不受影响。

### 发布与线上
11. 新 Mac ZIP + `updates/mac.json` 部署到 VPS，`/api/update/mac` 返回新 build，
    公网 ZIP SHA256 与本地一致；`/Applications/CopySync.app` 安装后实测第 4~10 项。
12. 线上 web/android 回归正常；交接 txt 更新（版本、SHA256、行为变更、验收结果）。

## 三、约束

1. **最终效果与 V3 预览图一模一样，任何元素不得重叠**（硬性）。
2. **所有按钮必须有反馈**（硬性）。
2.1 **所有按钮无重叠且有反馈**（用户追加，与 1/2 合并为最高优先级硬性约束）。
3. 功能不丢：接收/发送/原生桥/截图快捷键/菜单栏/本地历史 10 条策略全部保留。
4. 原生改动集中在 CopySync.m；WebView 改动集中在 app.py 的 mac 区块；
   不得破坏 web / `?app=android`。
5. 不新增后端接口、不动数据库（复用 P1 的 keep/extend/history）。
6. 版本号递增；旧版更新链路（/api/update/mac）必须可用。
7. 发布走「构建 → SHA256 → 备份线上旧 ZIP → 替换 → 公网校验 → 安装实测」流程。
8. 上线后更新 VPS 交接 txt 的 CopySync 段，遵循 vps-inventory-handoff-manager 规范。
