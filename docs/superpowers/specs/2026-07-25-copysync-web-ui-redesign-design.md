# CopySync 网页版 UI 重设计 + 设备传输改造（方案 B · V7 定稿）设计文档

日期：2026-07-25（V7 定稿）
状态：已与用户确认（头脑风暴 + 可视化预览 V1→V7，用户逐版批注后批准 V7）

## 一、需求提炼（最终版）

### 背景
CopySync 前端是内嵌在 `app.py` 中 `INDEX_HTML` 的单文件 SPA，一套代码三种模式：
浏览器网页版（浅色）、安卓 App WebView（`?app=android`）、Mac App WebView（`?app=mac`，深色）。
本轮以网页版为主做视觉重设计（白色为主、简约大气），同时对「设备传输」做功能改造；
传输改造标注为**三端都改**（网页先行，安卓 / Mac 随后）。

### A. 视觉语言（方案 B 暖白卡片）
1. 米白底 `#faf9f7` + 白色悬浮卡片（1px `#eee9e2` 边框、14px 圆角、柔和阴影）
   + 低饱和墨绿 `#0b5c3e` 点缀（Logo、主按钮、选中 chip、钉住态）。白色为主、简约大气。
2. 登录页、入口选择页（/go）同步换新视觉。

### B. 网页版布局调整（纯 UI）
3. 删除顶栏「临时网盘 / 设备传输」两个标签（原本无功能的装饰 span）。
4. 删除网盘面板「临时网盘」标题，保留容量小字。
5. 网盘面板头部新增拖放上传框（虚线框，位于「上传」按钮左侧），复用现有拖拽上传逻辑。

### C. 交互反馈与钉子（纯 UI）
6. **所有可点元素都有反馈**：悬停 = 变深 + 微浮起 + 阴影；按下 = 下沉 + 内阴影；
   禁用 = 灰化 + 禁止指针；统一 0.15s 过渡。覆盖主按钮、次要按钮、chips、
   行内操作、钉子、拖放框（拖入高亮）。
7. **网盘每行前置钉子**：钉住 = 📌 原角度斜钉 + 墨绿；未钉住 = 📌 旋转 **-45°** + 灰色半透明。
   钉子即切换按钮；原行尾「固定」按钮移除（功能合并，行为不变）；钉住条目仍排最前。
8. **行内操作按钮统一**：续期 / 上传 / 复制 / 下载 / ✕ 全部同一字号、字重、颜色（中灰），
   仅悬停/按下时变化。

### D. 临时网盘行为调整（含后端）
9. 网盘新上传内容**默认保存 7 天**（不再跟随传输面板的 TTL 选择）。
10. 行内新增「**续期**」按钮：过期时间在 `max(当前过期时间, 现在)` 基础上顺延 7 天；
    适合不想钉住又想多留的内容；钉住仍为永久。需新增续期接口。

### E. 设备传输改造（含后端；**三端都改**，网页先行）
11. **删除「全部设备」选项**。目标仅 Android 手机 / Mac。默认目标：
    网页 → Android 手机；Mac → Android 手机；Android → Mac。
12. **取消「目标是否同步到网页」勾选框**：任何方向的传输，网页都自动保留记录（web 侧始终可见）。
13. **保留时间默认 1 天**（可选 4 小时 / 1 天 / 3 天 / 7 天），到期服务端自动删除文件
    （复用现有 cleanup timer 机制）。
14. 「最近传输」拆为两个区块：
    - **我的文件**：我收发的、**未过期**的内容（文本 + 文件），显示剩余时间；到期自动从此消失。
    - **传输记录**：完整历史（含已过期条目，灰显「已过期 · 文件已删」），**记录保留 30 天**。
      文件过期被删后记录仍在 —— 需要后端在清理文件时保留传输记录（deliveries 不再随 items
      删除而消失；记录保存条目的名称/类型/大小/方向/状态快照，30 天后清除记录）。
15. 「我的文件」行内新增「**上传**」按钮：把该文件/照片**转存到临时网盘**；
    文本则存为网盘文本条目；转存后按网盘规则默认 7 天，可续期/钉住。

### 明确不做（YAGNI）
- 不改 SSE 推送、登录/鉴权、Cookie 策略、限速、nginx、端口、systemd 单元
- 不引入构建工具、不拆前端文件、不加依赖
- P1 不改 `?app=android` / `?app=mac` 专属样式与结构（不许破版；传输改造的三端 UI 适配在 P2/P3）
- 不改动 AnyVPS、Sub-Store 等同机其他服务

## 二、阶段目标

| 阶段 | 内容 | 状态 |
|---|---|---|
| **P1（本次）** | 网页版：A/B/C 视觉与交互 + D/E 网盘与传输行为（含所需后端接口） | 本次实施 |
| P2（后续） | 安卓 App 界面统一新视觉 + 传输改造落地（默认目标 Mac、我的文件/传输记录、转存、续期） | 另起任务 |
| P3（后续） | Mac App 界面统一（深色是否转白届时再定）+ 传输改造落地 | 另起任务 |

### P1 实施要点
- **前端**（`INDEX_HTML` 内）：默认（网页）样式全量换新；顶栏删 navlinks；drive-head 改为
  拖放框 + 上传；file-row 首列加钉子（-45°/0° 两态）；行尾固定按钮移除；行内操作样式统一；
  传输面板去掉「全部设备」与 syncWeb 勾选；TTL 默认选中 1 天；「最近传输」替换为
  「我的文件」+「传输记录」两个区块；登录页与 /go 页换新。
- **后端**（`app.py`，同文件改动，保持单文件）：
  - 网盘上传默认 TTL = 7 天（前端不再把 transferTtl 用于网盘上传；后端默认值同步调整）。
  - 新增 `POST /api/renew`（或等价）：`expires_at = max(expires_at, now) + 7 天`，pinned 条目拒绝/无操作。
  - 新增「转存网盘」接口（或复用现有条目更新）：将传输条目转为网页可见 + 过期时间重置为 now + 7 天。
  - 传输记录持久化：deliveries 增加条目快照字段（name/kind/size/text 摘要/方向），cleanup 删除
    过期 item 文件时保留 delivery 记录并标记 expired；新增/调整 `/api/transfers` 输出
    「我的文件」（未过期）与「传输记录」（30 天历史）两段数据；记录超 30 天由 cleanup 清除。
  - TTL 默认：传输表单默认 86400（1 天）；`DEFAULT_TTL_SECONDS` 语义拆分（网盘 7 天 / 传输 1 天）。
- **数据库**：仅做**增量**变更（加列/加表 + 惰性迁移），不丢现有数据；部署前备份 `clipboard.db`。
- **风险点**：共享 CSS 类（`.panel`/`button`/`.chip`）被 android-app 引用，改默认样式后必须核对
  `?app=android`、`?app=mac` 不破版；mac 视图有自有变量覆盖，android 同为白色系可接受微调渗透。
- **响应式**：`@media 900px / 520px` 同步核对（移动端 drive-head 换行、行内操作换行、传输面板堆叠）。

## 三、验收准备

### 本地验证（改完先跑）
1. `python3 test_app.py` 现有测试全部通过；为续期 / 转存 / 传输记录 30 天保留新增测试。
2. 本地启动，核对四种页面：登录页、/go、网页主界面、`?app=android`、`?app=mac`（后两者不破版）。
3. 网盘：上传（按钮 + 拖入上传框 + 拖入列表区）默认 7 天；钉子 -45°↔0° 切换与排序；
   续期顺延 7 天；复制 / 下载 / 删除 / 清理临时内容；搜索与筛选。
4. 传输：目标无「全部设备」、默认 Android；TTL 默认 1 天；发送文本/文件；
   我的文件只显示未过期内容且带剩余时间；「上传」转存网盘成功（文件→网盘文件、文本→网盘文本）；
   传输记录在文件过期删除后仍保留并灰显已过期，30 天后清除。
5. 按钮反馈：主按钮 / chips / 行内操作 / 钉子 / 拖放框逐个核对悬停、按下、禁用三态。
6. 响应式 <900px 与 <520px 布局正常。

### 线上验收（部署到示例 VPS 后）
1. 部署前备份：`app.py` 与 `data/clipboard.db` 各一份带时间戳备份。
2. 重启 `copy-example.service`：active、`NRestarts` 不增长、日志无异常。
3. 三入口 HTTP 200（copy / copy-direct / copy-cf）+ 两个 healthz 200。
4. 线上实操：登录 → 上传（含拖放框）→ 续期 → 钉住 → 发送传输 → 我的文件转存网盘 →
   检查传输记录 → 清理测试数据。
5. Mac / Android 真机 App 打开确认 WebView 不破版、收发正常（P1 不改其结构）。
6. 视觉效果与 V7 mockup 一致。

### 回滚
恢复 `app.py` 与 `clipboard.db` 备份并重启服务；DB 迁移仅增量，旧代码可直读旧库。

## 四、约束

1. 前端仍单文件内嵌 `INDEX_HTML`；不拆文件、不加依赖、不引入构建工具。
2. 后端改动集中在 `app.py`；数据库仅增量迁移（加列/加表），不得丢数据、不得改坏旧数据语义。
3. `?app=android` / `?app=mac` 现有视图不许破版（P1 只做防御性核对，不主动改其结构样式）。
4. 端口 15080、systemd、nginx、Cookie 策略、限速、登录凭据全部不动。
5. 部署必须走「备份 → 替换 → 重启 → 验证 → 清理测试数据」流程。
6. 上线后更新 VPS 交接 txt 的 CopySync 段（新行为说明 + 验收结果），遵循 vps-inventory-handoff-manager 规范。
7. **最终 web 效果必须与 V7 mockup 一模一样，任何元素不得出现重叠**（用户追加，硬性约束）。
